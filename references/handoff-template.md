# 项目交接模板

以下结构用于辅助判断，不是必须逐项填写的固定表单。根据项目实际情况删除不适用的章节，并沿用用户使用的语言。

## 可复制到新对话的首条消息

```text
请继续处理：[项目名称或明确目标]

项目与工作目录
- 项目：[名称]
- 唯一工作目录：[绝对路径]
- 当前阶段：[一句话说明]

开始前先读取
1. [最高优先级项目规则]
2. [当前需求或规格]
3. [其他必要来源]

规范与授权边界
- [来源优先级]
- [不得自动执行的动作]
- [需要明确确认的文案、业务规则或外部操作]
- [明确弃用或不得修改的文件]

已经完成
- [结果 + 具体文件路径 + 验证情况]

当前有效文件
- [文件路径：用途]

已知问题或未完成工作
- [当前可复现问题、影响和证据]

待确认事项
- [不得描述为已实施的方案或业务规则]

已完成验证
- [实际执行的静态、浏览器、数据或人工检查]
- [没有覆盖的验证边界]

建议的下一步
1. [最安全、最明确的后续动作]

请先读取上述规范并核对当前工作区状态，再根据我的下一条具体要求执行；不要自行扩展范围。
```

## 质量要求

- 本地文件应使用绝对路径，确保新对话可以准确定位。
- 保留准确的产品名称、版本、状态、时间范围和数据口径。
- 建议方案和未决问题必须标记为 `待确认`。
- 说明每项结果属于已实现、草拟、已验证还是仅讨论。
- 只有在影响安全续接时，才说明未提交或无关的工作区改动；不得暗示这些改动属于当前任务。
- 只保留会影响后续工作的关键历史，不要复述完整对话过程。
- 大型项目应指出每个子系统的权威事实来源，不要复制所有原文。
- 无法进行实际验证时，应说明已完成的静态检查以及仍未验证的内容。
